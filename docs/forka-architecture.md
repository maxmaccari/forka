# Forka context map and architecture audit

Baseline reviewed on 2026-11-21 at `27fd72c8d8dc136349616a1258cfbebaa1d8e54a` for [MAX-45](https://linear.app/maxmaccari/issue/MAX-45/establish-and-audit-forkas-architecture-baseline). The [shared architecture guide](architecture.md) defines the target architecture.

## Context ownership

| Context | Owns | Public API and observed dependencies |
| --- | --- | --- |
| [Games](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games.ex) | `games`, `game_players`, `game_words`, and `events`. The per-game process holds a loaded aggregate. | Lists and creates games, accepts lobby and match commands, returns game summaries, and manages subscriptions. It reads the Words schema and maps the Players table through a second schema. |
| [Players](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/players.ex) | `players` and `players_tokens`. | Registers players and handles credentials, sessions, confirmation, email changes, and password resets. It calls no other domain Context. |
| [Words](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/words.ex) | `words` and `categories`. | Imports words and lists categories. It calls no other domain Context. |
| [Backoffice](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/backoffice.ex) | `admins` and `admins_tokens`. | Handles admin registration, credentials, sessions, confirmation, email changes, and password resets. It calls no other domain Context. The Backpex web resources access their Contexts' schemas under the [admin ADR](adrs/0002-backpex-admin-boundary.md). |

The runtime Context dependency graph has two outgoing edges from Games, to Players' storage and Words' schema. Neither Context depends on Games. Backoffice is separate from the Backpex resources in the web layer.

## Guess command

1. [PlayerAuth](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka_web/player_auth.ex) resolves the session token through Players and assigns `current_player`. The [router](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka_web/router.ex) has player authentication routes. A future room LiveView will derive the actor from the authenticated session and pass a player scope to Games.
2. [Games.guess/3](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games.ex#L221) accepts a game ID, player ID, and letter, then ensures the game process is available. [GameServer](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/game_server.ex#L206) serializes commands and delegates the decision to `Core.guess/3`.
3. [GameLogic](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/core/game_logic.ex#L78) checks match status and turn ownership, then applies the guess, updates the aggregate, and records events. Guess and event constructors currently read the clock. The shell should supply time and other nondeterministic inputs.
4. [Repository.save_game_state/1](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/repository.ex#L183) reloads and preloads the game, then uses one Ecto association update to persist the aggregate. It publishes the Backpex update after the write. The server then publishes a detail summary and sends a list update when its projection changes. On success it replies and retains the state returned by persistence.

Keep actor and membership enforcement in Games, with permission checks running against the same state used to decide the command. Keep aggregate writes and event inserts inside the Games transaction. Load external Context data beforehand and publish projections for each audience after commit. See the [process recovery ADR](adrs/0001-game-process-ownership.md).

| Before room and match routes | Games accepts caller-supplied actor IDs and has owner commands with no actor parameter. Summary and subscription APIs accept a game ID without membership checks. `list_games/1` returns persistence schemas, and `GameSummary` includes schema structs and event payloads. | Before room and match routes | Games maps the Players-owned `players` table and queries `Words.Word` directly. [Player schema](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/schemas/player.ex#L17), [dictionary query](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/repository.ex#L45), [migrations](https://github.com/maxmaccari/forka/tree/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/priv/repo/migrations) | Give Players and Words public data APIs, declare the one-way dependencies, and keep Games-owned snapshots where history must survive. Review admin deletion, backfill affected records, and migrate foreign keys with deletion-behavior tests. |
| Before relying on room recovery | Startup reads the aggregate on the supervisor's startup path and the facade checks process existence before dispatch. Timeout can archive a game. The aggregate update uses no optimistic lock. [Startup](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/game_server.ex#L31), [dispatch](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games.ex#L339), [timeout](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/game_server.ex#L258), [write path](https://github.com/maxmaccari/forka/blob/27fd72c8d8dc136349616a1258cfbebaa1d8e54a/lib/forka/games/repository.ex#L183) | Move loading into the child, make idle stop preserve persisted state, and test crash reload and concurrent start through the supervisor.
